## 서버 채점

`quiz-grade`는 Firebase ID 토큰 서명·만료·발급자·대상을 검증하고, 해당 토큰으로 Firebase 데이터를 다시 읽는다. 브라우저가 보낸 점수·답·경과 시간을 채점 근거로 사용하지 않는다. 진행자 요청만 공개·점수·리포트를 기록하고 학생 요청에는 본인이 제출한 문제의 결과만 반환한다. Admin 키나 새 서비스 계정은 필요하지 않으며 Firebase의 기존 권한도 매 요청에 적용된다. 기존 AI 함수는 변경하지 않는다.

공개 전 `grading` 상태로 제출을 닫고 다시 읽은 답안을 계산한다. 결과는 누적 재가산하지 않으므로 공개 요청을 재시도하거나 진행자 화면을 복구해도 점수가 중복되지 않는다. 개인 학습·클래스 누적 기록·결과 화면도 같은 서버 계산식을 사용한다. 네트워크/채점 서버 오류에서는 임의의 로컬 점수를 저장하지 않는다. 교사는 자기 수업과 저장된 퀴즈·결과를 관리하는 신뢰 주체이며, 교사 본인의 데이터 편집까지 방지하는 감사 시스템은 아니다.

완료 후 공개는 학생의 마지막 문항 제출 또는 교사 종료 전 정답 키를 차단한다. 자기 퀴즈를 직접 학습하는 소유자는 원래 자신의 퀴즈/정답에 접근할 수 있다.

## 실행 및 관찰

- `npm test`: 21개 통과 (기존 AI·점수·분석·슬라이드 및 새 서버 채점).
- Java 21 + `npm run test:rules`: 12개 통과 (교사/학생/타인 권한, 시간/중복 제출, 클래스/개인 학습, 완료 전 키 차단).
- `QUIZ_LIVE_TEST=1 npm run test:browser:live`: 실제 Firebase 익명 계정과 배포된 채점 함수로 수업·경주·재접속·개인 학습·리포트/CSV·완료 후 공개를 자동 확인. 문제만 두 문항으로 대체하며 인증·DB·서버 채점은 실제 연결이다. 생성한 임시 세션·정답·기록·익명 계정을 정리한다.
- 별도 운영 REST 검증: 수업/개인 점수, 재요청 중복 방지, 학생의 타인 리포트 요청 거부, 잘못된 ID 토큰 거부.
- 실제 Google 로그인 팝업과 Gemini 생성은 이번 운영 자동 검증에서 실행하지 않았다. 관련 코드는 유지하며 기존 AI 단위 검사를 실행했다. 클래스의 Google 권한은 Firebase 에뮬레이터로 검증했다.

## 배포

Firebase Cloud Functions는 Blaze 플랜이 필요하여 사용하지 않는다. 이미 연결된 Supabase에 `quiz-grade`를 배포하고 Firebase RTDB는 그대로 사용한다. 이 함수는 외부 Firebase 토큰을 자체 검증하므로 Supabase의 `verify_jwt=false`로 배포한다. `quiz-ai`의 설정과 코드에는 영향이 없다.

운영 규칙을 먼저 백업·비교한 뒤 완료 후 공개 조건 한 항목만 강화한다. 이어서 PR의 단위/규칙 CI를 확인하고 main에 병합해 GitHub Pages의 배포 커밋과 실제 제공 파일을 확인한다. PWA 캐시를 갱신하고 누락된 기존 슬라이드 파일도 오프라인 목록에 포함한다.
